# 热点雷达：主要产品与开发大纲

版本：0.2.0；方案确认：腾讯＋BaoStock 作为共享行情源，舆情属于本软件内部模块。

## 1. 产品目标与边界

从「热门方向正在形成」到「候选股满足研究条件」，再到「持仓风险持续跟踪」。观察主线扩散与趋势延续，不把事后涨停榜当成提前选股能力，不声称预测下一只涨停。

独立部署、独立配置、独立数据库、独立计划与账本。与 stock_t_alert 只共用行情 REST 服务；不读取其持仓、下单、控制或计划接口。腾讯＋BaoStock 是一个数据服务，本软件是第二个服务；题材和舆情不是额外常驻服务。

## 2. 整体架构

```text
腾讯公开行情 + BaoStock历史数据
        ↓ 已有只读行情服务
        ├── stock_t_alert（原系统保持原样）
        └── hotstock/shared_market.py
                  ↓
公开题材/日历/涨停 → 内置题材任务 → 标准行情包 → 规则引擎
公开快讯/公告目录 → 内置消息任务 → 事件版本库 → 关联风险复核
                                               ↓
                              候选、冻结计划、独立持仓账本、提醒
                                               ↓
                                    中文网页 / JSON API / Webhook
```

主程序使用 FastAPI + SQLite。价格监控与公开研究采集分线程，AKShare 请求在有限时长子进程中运行，不允许慢新闻采集持有风控锁。部署只运行一个主程序进程（uvicorn workers=1），避免重复调度。

## 4. 数据采集分工

### 4.1 行情

服务根地址、Bearer Token 由用户配置。新适配器只调用 `/ready`、`/api/quote`、`/api/bars`，不调用旧软件业务 API。当前支持沪深代码；AmazingData 不作为备用源。

查询预算最多100个报价，默认由配置控制；最多12只股票拉取历史日线，缓存30分钟。已有持仓和人工观察股票优先，随后按主题成员交错挑选，避免单个题材占满。仍保留完整成员分母；覆盖不足不会被美化成完整板块统计。订单请求不存在。

源端 `stale=true` 不因刚获取就变新。缺少昨收、未来行情、单位不符、日线复权不明均不生成可执行判断。当前标准报价没有证券交易元数据，因此“严格入场阻断”是已知限制，不是可直接实盘交易的验收通过。

### 4.2 题材与热度

默认30分钟（最低15分钟）获取一次研究信息：概念目录→选主题→完整成员→日历→当日涨停池。不是高频全市场扫单。失败独立记录；原成员的 known_at 不随重读缓存更新。跨日/陈旧成员退回未知质量。

当前热度与策略来自行情规则，不把新闻转载次数算作新增利好，也不把分数展示成上涨概率。

### 4.3 消息

默认15分钟（最低5分钟）。每轮最多5只股票，默认3只；持仓与观察名单、行情候选组成轮换队列，任务结果显示实际覆盖的股票。不能承诺每个持仓每轮都有完整新闻。

财联社为窗口快讯；东方财富检索结果不一定都属于查询股票，因此只有原文含其代码才自动关联；巨潮公告目录依据返回股票代码关联，正文未读取时明确 title_only。普通新闻中的公司简称关系识别暂不自动确认。

## 5. 事件状态与时间语义

- pending：待核实；tracking：跟踪；reviewed：人工已复核；disproved：已澄清/证伪；closed：关闭。
- 任意状态修改必须写理由，证据链接可另附；记录时间由系统生成，不允许用户倒填。
- published_at/occurred_at 缺失保持 null；未来计划写在正文，不能填成已发生时间。
- first_seen_at 是首次真正导入的时间，不能用发布日期代替。
- 同文重复不新增版本；同URL内容变化追加不可变版本；同标题/同日/同证券集合保守归并。未实现语义聚类，不能声称各种改写都被识别。
- 转载来源数量不等于相互独立的确认次数；官方域名仅是来源属性，不自动把事实标成 verified。
- 复核后新风险版本重新进入待核实；好消息不能自动解除先前待核实风险。
- 历史时点查询只看当时已获取的文章和复核记录，不能使用未来版本。

## 6. 风险联动及 AI 分工

关键词风险是提醒人工核对，不是对事实的结论；可能误报。默认暂停相关新增计划，并在候选和计划页面显示阻断原因。底层冻结计划的价格锚点不变，原价格风险监控继续，手工成交记录只反映外部已发生的交易。

AI 为可选、手动的单事件摘要。必须显式启用，独立配置端点/模型/Key，只发送当前文章（不发送持仓、Token、其他数据库）。要求 JSON 结构与可在原文找到的连续证据摘录；校验失败不保存摘要。无工具执行、不修改规则、仓位、止损或事件复核状态。摘要即使验证摘录也不代表事实已核实。

## 7. 安全、凭据与运行

默认演示、自动采集关闭。API Key 用于本软件鉴权；MARKET_MCP_TOKEN 只用于行情数据服务，两者不同。界面不回显密钥，配置导出脱敏；本地数据库仍可能包含手工保存的 Token，应保护磁盘/备份权限，不公开上传数据目录。

公开仓库不得包含 stock_t_alert 的私有 .env、供应商授权、交易密码或 SDK。公网必须使用 HTTPS、访问控制和防火墙；内网 HTTP 传输 Bearer 需显式确认。

## 8. 分期与验收

本版：代码/API/离线契约测试完成；真实服务接线、公开数据可用性、通知送达和 AI 真实调用由部署验收完成。

下一优先级：可信证券元数据（当日涨跌停价、交易单位、停牌）、批量/缓存服务负载、持仓报价覆盖保障、公告正文与证据关系。再做长期题材状态、情绪研究和样本外回测，不先扩展自动交易。

验收必须覆盖正反向：正确来源成功；错Token/上游错误失败；陈旧行情阻断；未知复权拒绝历史；数据不足不补假值；重新闻不加热；未来文章拒绝；未复核风险暂停；止损不因好消息放宽；所有失败可见且不回退 DEMO。
